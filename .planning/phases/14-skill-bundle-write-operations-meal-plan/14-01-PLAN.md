**Title:** `# Create a recipe`

**Section: Create recipe**

H2: `## Create recipe`
H3: `### Endpoint`
```
POST /api/recipes
```
Authentication required (see `shared.md`). Creates a new recipe in the authenticated user's household. A default ingredient section is auto-created (see Recommended sequence below).

Status codes:
- `201` — created
- `400` — validation error

H3: `### Request body`
Field table with columns: Field | Type | Required | Description

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| name | string | Yes | Recipe name |
| description | string | No | Plain text description |
| servingsQty | integer | No | Number of servings (must be integer, not decimal) |
| servingsUnit | string | No | Servings label (e.g., "porciones") |
| prepTime | integer | No | Preparation time in minutes |
| cookTime | integer | No | Cooking time in minutes |
| totalTime | integer | No | Total time in minutes |
| performTime | integer | No | Active hands-on time in minutes |
| sourceUrl | string | No | Must be a valid URL if provided |

H3: `### Response`
Full `RecipeDetailResponse` — same shape as `GET /api/recipes/:id` (see `recipes_get.md`). The response includes a `sections` array with one auto-created default section.

**Section: Resolve food and unit IDs**

H2: `## Resolve food and unit IDs`

Ingredients require a `foodId` (required) and optionally a `unitId`. Resolve these from the reference lists before adding ingredients.

H3: `### List all foods`
```
GET /api/foods
```
Returns ALL foods as a plain array (not paginated). No query parameters are supported — the endpoint does not accept a `search` parameter.

Response item shape:
```json
{ "id": "uuid", "name": "Huevo" }
```

To find a specific food, scan the array by `name` (case-insensitive match recommended).

H3: `### List all units`
```
GET /api/units
```
Returns ALL units as a plain array (not paginated). No query parameters are supported.

Response item shape:
```json
{ "id": "uuid", "name": "kilogramo", "abbreviation": "kg" }
```

**Section: Add a section**

H2: `## Add a section`
H3: `### Endpoint`
```
POST /api/recipes/:id/sections
```
- `201` — created
- `403` — recipe belongs to a different household
- `404` — recipe not found

H3: `### Request body`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| title | string | No | Section title; omit for an unnamed section |

H3: `### Response`
```json
{ "id": "s1s2s3s4-...", "title": "Salsa", "order": 1, "ingredients": [] }
```

**Section: Add an ingredient**

H2: `## Add an ingredient to a section`
H3: `### Endpoint`
```
POST /api/recipes/:id/sections/:sectionId/ingredients
```
- `201` — created
- `400` — validation error
- `403` — recipe belongs to a different household
- `404` — recipe or section not found

H3: `### Request body`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| foodId | string (UUID) | Yes | Food ID from `GET /api/foods` |
| unitId | string (UUID) | No | Unit ID from `GET /api/units` |
| quantity | number | No | Amount (can be decimal, e.g., 0.5) |
| note | string | No | Additional note (e.g., "finely chopped") |

H3: `### Response`
```json
{
  "id": "i1i2i3i4-...",
  "foodId": "f1f2f3f4-...",
  "foodName": "Huevo",
  "unitId": "u1u2u3u4-...",
  "unitName": "unidad",
  "quantity": 6,
  "note": null,
  "order": 0
}
```

**Section: Add a step**

H2: `## Add a step`
H3: `### Endpoint`
```
POST /api/recipes/:id/steps
```
- `201` — created
- `403` — recipe belongs to a different household
- `404` — recipe not found

H3: `### Request body`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| body | string | Yes | Instruction text |
| title | string | No | Optional step heading |

H3: `### Response`
```json
{ "id": "st1st2st3-...", "title": null, "body": "Batir los huevos con sal.", "order": 0 }
```

**Section: Recommended sequence**

H2: `## Recommended sequence`

A numbered list:

1. **Create the recipe** — `POST /api/recipes` with at least `name`. The response includes `id` (the recipe ID) and `sections[0].id` (the auto-created default section ID).
2. **Resolve food and unit IDs** — `GET /api/foods` and `GET /api/units`. Scan each list by name to find the matching `id`. Cache the results for reuse across ingredients.
3. **Add ingredients to the default section** — `POST /api/recipes/:id/sections/:sectionId/ingredients` using `sections[0].id` from step 1 as `:sectionId`. Repeat for each ingredient.
4. **(Optional) Add named sections** — `POST /api/recipes/:id/sections` with a `title`. Use the returned `id` as `:sectionId` for ingredients in that section.
5. **Add steps** — `POST /api/recipes/:id/steps` for each instruction step. Steps are ordered by creation order.

**Section: Example**

H2: `## Example`

Full worked example showing the sequence:

Step 1 — Create recipe:
```
POST /api/recipes
```
Request body:
```json
{ "name": "Tortilla espanola", "servingsQty": 4, "servingsUnit": "porciones", "prepTime": 15, "cookTime": 20, "totalTime": 35 }
```
Response (abbreviated):
```json
{ "id": "r1r2r3r4-...", "sections": [{ "id": "s1s2s3s4-...", "title": null, "order": 0, "ingredients": [] }], "steps": [], "images": [] }
```

Step 2 — Add ingredient (after resolving foodId and unitId from GET /api/foods and GET /api/units):
```
POST /api/recipes/r1r2r3r4-.../sections/s1s2s3s4-.../ingredients
```
Request body:
```json
{ "foodId": "f1f2f3f4-...", "quantity": 6, "unitId": "u1u2u3u4-...", "note": null }
```

Step 3 — Add step:
```
POST /api/recipes/r1r2r3r4-.../steps
```
Request body:
```json
{ "body": "Batir los huevos con sal." }
```

**Title:** `# Edit a recipe`

**Guidance note** (immediately after title):
Always fetch the current recipe via `GET /api/recipes/:id` (see `recipes_get.md`) before editing. This gives you the correct sub-resource IDs (section, ingredient, step) needed for update and delete operations.

If `isLocked` is `true` in the response, the recipe cannot be edited. To unlock, send `PATCH /api/recipes/:id` with `{ "isLocked": false }` first.

**Section: Update recipe metadata**

H2: `## Update recipe metadata`
H3: `### Endpoint`
```
PATCH /api/recipes/:id
```
Partial update — include only the fields you want to change.

- `200` — updated
- `400` — validation error
- `403` — recipe belongs to a different household
- `404` — recipe not found

H3: `### Request body`

All fields are optional:

| Field | Type | Nullable | Description |
|-------|------|----------|-------------|
| name | string | No | Recipe name |
| description | string | Yes | Set `null` to clear |
| servingsQty | integer | Yes | Set `null` to clear |
| servingsUnit | string | Yes | Set `null` to clear |
| prepTime | integer | Yes | Set `null` to clear |
| cookTime | integer | Yes | Set `null` to clear |
| totalTime | integer | Yes | Set `null` to clear |
| performTime | integer | Yes | Set `null` to clear |
| sourceUrl | string | Yes | Set `null` to clear; must be a valid URL if non-null |
| isLocked | boolean | No | Set `true` to lock, `false` to unlock |

H3: `### Response`
Full `RecipeDetailResponse` (see `recipes_get.md`).

H3: `### Example`
Request:
```
PATCH /api/recipes/a1b2c3d4-...
```
Request body:
```json
{ "description": "Receta actualizada", "cookTime": 25 }
```

H3: `### Response`

|-------|------|----------|-------------|

`IngredientResponse` (same shape as in `recipes_get.md` nested ingredients).

| title | string | Yes | Set `null` to remove title |

H3: `### Response`
`StepResponse`: `{ "id": "...", "title": null, "body": "Updated instruction.", "order": 0 }`

**Section: Delete operations**

H2: `## Delete operations`

All delete endpoints return `200` on success. No request body is needed.

A Markdown table:

| Endpoint | What it deletes |
|----------|-----------------|
| `DELETE /api/recipes/:id` | The entire recipe and all sub-resources (sections, ingredients, steps, images) |
| `DELETE /api/recipes/:id/sections/:sectionId` | The section and all its ingredients |
| `DELETE /api/recipes/:id/sections/:sectionId/ingredients/:ingredientId` | A single ingredient |
| `DELETE /api/recipes/:id/steps/:stepId` | A single step |

Status codes for all delete operations: `200` (success), `403` (wrong household), `404` (not found).

- To manage images (upload/delete): see `recipes_image.md`.
- To create new sub-resources (sections, ingredients, steps): see `recipes_create.md`.
- Authentication and error codes: see `shared.md`.
