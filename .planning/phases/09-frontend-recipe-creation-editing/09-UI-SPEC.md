## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, drag handle gutter, inline badge padding |
| sm | 8px | Gap between label and input, icon-to-text gap in buttons |
| md | 16px | Default element spacing, form field vertical rhythm |
| lg | 20px | Horizontal page padding (matches established `px-5`) |
| xl | 24px | Section vertical padding, tab content top padding |
| 2xl | 32px | Scroll buffer above FAB, bottom sheet top padding |
| 3xl | 48px | Bottom safe-area clearance for fixed FAB + Guardar pill |

Exceptions:
- Touch targets for drag handles: minimum 44px tall row (12px top/bottom padding + content)
- Bottom sheet drag handle bar: 36px wide × 4px tall, centered, `bg-border`, `border-radius: 2px`
- Tab bar tab height: 44px (accessibility minimum)
- FAB: 56px × 56px, `border-radius: 16px`
- Guardar pill: `px-6 py-3`, `border-radius: 9999px` (pill shape), fixed bottom-right

**Source:** `mvp_plans/06_hifi_wireframes.md` component patterns; `apps/web/src/components/layout/Drawer.tsx` and `TopBar.tsx` for existing `px-5/px-6` patterns.

## Color

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `background` | `#FAFAF7` | App background, bottom sheet background, full-screen modal background, form input backgrounds, image upload zone background |
| Secondary (30%) | `sand` + `subtle` | `#E8E1D5` / `#F4F2ED` | Top bars (detail/creation), drawer header (`sand`); section accordion headers, search bar, stat boxes (`subtle`) |
| Accent (10%) | `accent` | `#5EBD6A` | FAB background, active tab underline (2px), active nav item underline, "Crear" confirm button fill, food picker selected-item checkmark, lock-active indicator |
| Destructive | `destructive` | `#D94F4F` | Delete ingredient button, delete step button, delete image link, logout (already in use) |

**Accent reserved for:** FAB, active tab indicator underline, "Crear" bottom sheet confirm button, food picker selected-state checkmark, lock-active state visual indicator. Do not use accent for general interactive elements, form inputs, or hover states.

**Additional color notes:**
- `foreground` (`#2C2C2A`): All primary text, filled button background, step number circle fill, drag handle icon color.
- `secondary` (`#8A8680`): All secondary/meta text, labels, inactive icons.
- `border` (`#E0DCD5`): Input underlines, dividers, outline button stroke, bottom sheet drag handle.
- `subtle` (`#F4F2ED`): Section accordion header backgrounds, food picker category group headers.
- Scrim overlay for bottom sheet and full-screen modal: `rgba(44, 44, 42, 0.35)`.
- Dashed upload zone border: `2px dashed #E0DCD5` (`border-dashed border-border`).
- Drag handle icon (`GripVertical` from Lucide): `text-placeholder` in idle, `text-secondary` while dragging.

## Interaction States

### Edit Mode Toggle
- Entry: "Editar" button on detail page top bar overflow menu, or `?edit=1` query param on load (after creation)
- Local React state — not a URL change
- In edit mode: drag handles and delete buttons appear in reserved space (no layout shift); "Editar" button becomes "Listo" (checkmark icon)
- Exiting edit mode ("Listo"): if Basico form has unsaved changes, show inline prompt "¿Guardar cambios?" with "Guardar" / "Descartar" options

### Drag-and-Drop
- Library: `@dnd-kit/core` + `@dnd-kit/sortable` + `@dnd-kit/utilities`
- Strategy: `verticalListSortingStrategy` for both ingredient rows and step rows
- Drag handle only triggers drag (not the full row)
- While mutation is in flight (`isPending`): drag handles are disabled (`pointer-events-none opacity-50`)
- On drag end: optimistic local state update first, then fire reorder mutation; on error: revert local state + toast "Error al reordenar"

### Form Input Focus
- All text inputs: no border change on focus (underline inputs), just browser default caret
- Textareas: `outline-none ring-2 ring-accent` on focus (bordered inputs only)
- Food search: auto-focuses on picker open

### Loading States
- Inline mutations (add/remove/reorder sub-resources): row-level skeleton or spinner, not full-page
- Image upload: progress indication via "Subiendo..." overlay on upload zone (no progress bar — not required by spec)
- Duplicate action: button loading state "Duplicando..."
- Full recipe fetch on page load: existing Skeleton component

### Error States
- API mutation failure: Sonner `toast.error(...)` — see copywriting contract below
- Form validation (empty name in RecipeNamePrompt): "Crear" button stays disabled, no inline error message
- Image upload failure: `toast.error('Error al subir la imagen. Intenta de nuevo.')`

## Design Principles (Inherited from Phase 7–8)

These are locked decisions from the established design system — do not override:

1. **Green is accent only.** `#5EBD6A` for FAB, active tab underline, Crear button. Never as a background for cards, panels, or hover states.
2. **Sand adds warmth.** `#E8E1D5` for the detail/creation top bars. Keeps the editor feeling connected to the content.
3. **Minimal chrome.** No box shadows on cards. No gradients. Single 1px `border-subtle` dividers only.
4. **No layout shift in edit mode.** Drag handles and delete buttons appear in reserved space — rows must be sized consistently in both view and edit modes.
5. **Content-first.** The "Guardar" pill overlays content rather than pushing it up.
