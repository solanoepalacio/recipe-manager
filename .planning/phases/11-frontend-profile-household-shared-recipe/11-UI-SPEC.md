## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline gaps between sibling text |
| sm | 8px | Compact element spacing, label-to-input gap |
| md | 16px | Default section padding, form field padding |
| lg | 24px | Section-level vertical separation |
| xl | 32px | Page top/bottom padding |
| 2xl | 48px | Major section breaks (e.g., between page sections) |
| 3xl | 64px | Page-level vertical padding (login page only) |

Exceptions:
- Touch targets (buttons, row taps): minimum 44px tall per WCAG 2.5.5 — use `py-3` (12px) + content to reach 44px; icon-only buttons use `w-[44px] h-[44px]`
- Form input rows: `py-4 px-4` (16px vertical, 16px horizontal) — established in LoginPage
- Card thumbnails: 72×68px — established in RecipeCard; not a spacing token, a fixed dimension

Source: Observed throughout Phases 7–10 components

## Views in This Phase

### View 1: Profile Page — `/profile`

**Layout:** Standard app shell (TopBar + Drawer). Page title: "Perfil".

**Sections:**
1. **Profile header** — avatar initial (first letter of name in a circle, bg-subtle, text-foreground, 48px diameter), user name at 20px semibold, username or email at 13px text-secondary below.
2. **Edit form** — field rows for: Nombre (text), Correo electrónico (email), Usuario (text), Contraseña (password, with "Cambiar contraseña" label toggle pattern to reveal field). All fields use established input style: `bg-subtle border-[1.5px] border-border rounded-[12px] py-4 px-4 text-[15px]`.
3. **Save CTA** — full-width pill button at bottom: `bg-foreground text-background rounded-[20px] py-4 text-[15px] font-semibold`. Label: "Guardar cambios".

**States:**
- Loading: Skeleton rows (h-[20px] and h-[48px] rounded-lg) matching field count
- Saving: Button shows `Loader2` spinner + "Guardando..." label, `disabled:opacity-60`
- Success: Sonner toast "Perfil actualizado"
- Error: Sonner toast "Error al guardar. Intenta de nuevo."
- Validation: email format error shown inline below field in text-destructive text-[13px]

### View 2: Share Link UI — on Recipe Detail Page (`/recipes/[slug]`)

**Trigger:** The existing "Compartir" placeholder button (already rendered, currently inert).

**Interaction pattern:** Tapping "Compartir" calls `POST /api/recipes/:id/share` to generate a token, then shows a **BottomSheet** (reuse existing `BottomSheet` component) with:
- Title: "Enlace para compartir" (15px semibold)
- Read-only URL input showing the full share URL (`window.location.origin + '/shared/' + token`), styled `bg-subtle border border-border rounded-[12px] py-3 px-4 text-[13px] text-secondary`
- Full-width button: "Copiar enlace" (bg-foreground text-background rounded-[20px] py-3 text-[15px] font-semibold)
- After copy: button label changes to "Copiado" for 2 seconds, then reverts (no toast — button label feedback is sufficient)
- Close: tap outside the sheet or a top drag handle dismisses

**States:**
- Generating token: BottomSheet opens with Skeleton in place of URL field
- Error generating token: Sonner toast "No se pudo generar el enlace. Intenta de nuevo." Sheet stays closed.

### View 3: Public Shared Recipe Page — `/shared/[token]`

**Layout:** NO app shell. Standalone public layout — no TopBar, no Drawer, no auth required. This is the `@Public()` route.

**Structure:**
1. **Minimal header strip** — `bg-sand px-5 py-4`. Left-aligned logo mark: `Utensils` icon (16px, text-accent) + app name "Robotina Cooks" (15px semibold text-foreground). No nav, no login link.
2. **Hero image** — full-width if recipe has images, 220px tall (same as recipe detail page pattern). Hidden if no images.
3. **Recipe name** — `text-[20px] font-semibold text-foreground tracking-[-0.3px]` in `px-5 pt-4 pb-3`.
4. **Info grid** — reuse `InfoGrid` component (prepTime, cookTime, totalTime, servingsQty, servingsUnit).
5. **Sections** — reuse `SectionAccordion` + `IngredientList` + `InstructionList` components. Same accordion expand/collapse interaction.
6. **Footer note** — `text-[13px] text-secondary italic text-center py-6 px-5`: "Compartido desde Robotina Cooks"

**States:**
- Loading: full-page centered Skeleton (3 rows of varying widths)
- Token not found / expired: centered message `text-[15px] text-secondary text-center`: "Este enlace no es válido o ha expirado." No redirect, no login prompt.
- Token valid: full recipe detail rendered read-only

## Interaction Patterns

### Profile form
- All fields editable inline — no "edit mode" toggle (unlike recipe detail). Form is always in edit state.
- PATCH fires on "Guardar cambios" button press only — no auto-save.
- Password field: initially hidden. A text button "Cambiar contraseña" (text-accent, 13px) reveals a `<input type="password">` field. Once revealed, it cannot be hidden again without page refresh.
- No inline field-level save — single save action for all profile fields.

### Share link flow
1. User taps "Compartir" on recipe detail header row.
2. Mutation fires `POST /api/recipes/:id/share` — button shows `Loader2` spinner during request.
3. On success: BottomSheet opens with the share URL displayed and "Copiar enlace" button.
4. On "Copiar enlace" tap: `navigator.clipboard.writeText(url)` called; button label changes to "Copiado" for 2s.
5. On error generating token: Sonner toast shown, sheet does not open.

### Public recipe page
- Read-only — no edit controls, no cook mode button, no share button.
- SectionAccordion starts collapsed (same default as recipe detail).
- No auth redirect — if token is invalid, show error message inline, not a redirect.

## Accessibility

- Profile form labels: explicit `<label htmlFor>` on each input field. Required fields have `required` attribute.
- Share sheet: trap focus inside `BottomSheet` while open. Close on Escape key (existing BottomSheet behavior assumed).
- Public page logo: `aria-label="Robotina Cooks"` on the header link/container.
- Avatar circle: `aria-hidden="true"` (decorative initial).
- Copy button: `aria-label="Copiar enlace al portapapeles"` in addition to visible label.
