**Content structure (in this order):**

1. **Title:** `# Meal Plan` (H1)

2. **Orientation paragraph:** "Load this skill when you need to read the household meal plan or add, move, and remove entries. The meal plan is per-household and entries are organized by date and meal type."

3. **Prerequisites** section (H2):
   - `RMAPI_BASE_URL` and `RMAPI_TOKEN` environment variables
   - Recipe IDs are needed to add entries (use `rmapi recipes list --fields id,name` to find them)
   - Dates use `YYYY-MM-DD` format (ISO 8601)
   - Valid meal types: `breakfast`, `lunch`, `dinner`, `snack`, `dessert`

4. **Read-Then-Mutate Pattern** section (H2) — the core workflow:
   ```bash
   # 1. Read current week's entries
   ENTRIES=$(rmapi meal-plan list --from 2026-03-20 --to 2026-03-27)

   # 2. Output is a JSON array (NOT a wrapper object)
   # Each entry has: id, date, type, recipe (with id, name, slug)
   echo "$ENTRIES" | jq '.[0]'

   # 3. Extract a specific entry ID for mutation
   ENTRY_ID=$(echo "$ENTRIES" | jq -r '.[] | select(.date=="2026-03-21" and .type=="dinner") | .id')

   # 4. Move the entry to a different day/meal type
   rmapi meal-plan move "$ENTRY_ID" --date 2026-03-22 --type lunch

   # 5. Remove an entry
   rmapi meal-plan remove "$ENTRY_ID" --yes
   ```

5. **Commands Reference** section (H2):
   - **List entries:** `rmapi meal-plan list` (all entries) or `rmapi meal-plan list --from YYYY-MM-DD --to YYYY-MM-DD` (date-filtered)
     - Output: JSON array of entry objects (not a wrapper — no `.entries` accessor needed)
     - Each entry: `{"id": "...", "date": "YYYY-MM-DD", "type": "dinner", "recipe": {"id": "...", "name": "...", "slug": "..."}}`
   - **Add entry:** `rmapi meal-plan add --recipe-id <id> --date YYYY-MM-DD --type dinner`
     - All three flags are required
     - `--type` choices: `breakfast | lunch | dinner | snack | dessert`
     - Returns the created entry with `id`
   - **Move entry:** `rmapi meal-plan move <entry-id> --date YYYY-MM-DD` and/or `--type lunch`
     - At least one of `--date` or `--type` should be supplied
     - Returns the updated entry
   - **Remove entry:** `rmapi meal-plan remove <entry-id> --yes`
     - Always include `--yes` (agent runs in non-TTY context)

6. **Common Workflow: Plan a Week** section (H2):
   ```bash
   # Find a recipe to plan
   RECIPE_ID=$(rmapi recipes list --search "pasta" --fields id,name | jq -r '.items[0].id')

   # Add it to Monday dinner
   rmapi meal-plan add --recipe-id "$RECIPE_ID" --date 2026-03-23 --type dinner

   # Check the week
   rmapi meal-plan list --from 2026-03-23 --to 2026-03-29
   ```

7. **Error Handling** section (H2):
   - Exit codes: 0 success, 1 API error, 2 auth failed, 3 not found, 4 validation error
   - If `meal-plan add` fails with exit code 3: the recipe ID does not exist; verify with `rmapi recipes get <id>`
   - If `meal-plan move` fails with exit code 3: the entry ID does not exist; re-fetch with `rmapi meal-plan list`
   - If `meal-plan remove` fails with exit code 4: missing `--yes` flag

```markdown
# rmapi Skill Index

Load this file at session start to discover available skills.
Load the relevant skill file only when you need to perform that task.

## Prerequisites

All skills require two environment variables:
- `RMAPI_BASE_URL` — API server URL (e.g., `http://localhost:3001`)
- `RMAPI_TOKEN` — API token for authentication

## Available Skills

| Skill File | What it covers |
|------------|----------------|
| [recipe-discovery.md](recipe-discovery.md) | Search, filter, sort, and retrieve recipes with field projection |
| [recipe-management.md](recipe-management.md) | Create and edit recipes: full ID-threading chain (lookup foods, create recipe, add sections, add ingredients, add steps), update, delete, duplicate, upload images |
| [meal-plan.md](meal-plan.md) | Read and modify the weekly meal plan: list entries by date range, add recipes to dates, move and remove entries |

## Exit Codes

All `rmapi` commands use consistent exit codes:

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | API error |
| 2 | Auth failure |
| 3 | Not found |
| 4 | Validation error |

## Output Convention

- Success: JSON to stdout
- Errors: JSON to stderr as `{"code": "...", "message": "...", "status": N}`
- All destructive commands (delete, remove) require `--yes` in non-interactive contexts
```
