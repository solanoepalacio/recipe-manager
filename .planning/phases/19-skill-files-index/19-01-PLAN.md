**Content structure (in this order):**

1. **Title:** `# Recipe Discovery` (H1)

2. **Orientation paragraph:** "Load this skill when you need to search, browse, or retrieve recipes from the household library. All commands output JSON to stdout."

3. **Prerequisites section** (H2):
   - `RMAPI_BASE_URL` and `RMAPI_TOKEN` must be set as environment variables
   - `jq` recommended for JSON field extraction (Python fallback: `python3 -c "import sys,json; print(json.load(sys.stdin)['id'])"`)

4. **Search and Browse** section (H2):
   - `rmapi recipes list` with all 7 options documented:
     - `--search "term"` — case-insensitive name substring
     - `--food-id <id>` — filter by food ingredient
     - `--sort name|createdAt|updatedAt|random` — sort order
     - `--order asc|desc` — direction
     - `--page N` — 1-based page number
     - `--per-page N` — items per page
     - `--fields id,name,...` — project items to named fields only
   - Output shape: `{"items": [...], "total": N, "page": N, "pageSize": N, "totalPages": N}`
   - Example: lightweight listing for decision-making: `rmapi recipes list --fields id,name --per-page 50`
   - Example: search with food filter: `rmapi recipes list --search "pasta" --food-id "$FOOD_ID" --sort name`

5. **Get Recipe Detail** section (H2):
   - `rmapi recipes get <id>` — returns full recipe detail (sections, ingredients, steps, images, metadata)
   - `rmapi recipes get <id> --fields id,name,description,sections,steps` — reduced fields to save tokens
   - Note: `--fields` operates on top-level keys only (cannot project nested fields within sections)

6. **Resolve Food and Unit IDs** section (H2):
   - `rmapi foods lookup --names "tomato,chicken"` — returns `[{name, id}]`; non-matching names silently omitted (exit code 0)
   - `rmapi units list` — returns `[{id, name, abbreviation}]`
   - `rmapi units list --fields id,abbreviation` — projected
   - Important: verify each input name appears in output; missing names mean the food does not exist in the database

7. **Error Handling** section (H2):
   - Exit codes: 0 success, 1 API error, 2 auth failure, 3 not found, 4 validation error
   - Errors go to stderr as `{"code": "...", "message": "...", "status": N}`
   - Successful output goes to stdout as JSON

8. **Tips** section (H2):
   - Use `--fields id,name` on list to minimize token usage when only IDs are needed
   - Use `--per-page 50` to get more results in one call
   - Chain food lookup into recipe search: `FOOD_ID=$(rmapi foods lookup --names "tomato" | jq -r '.[0].id')` then `rmapi recipes list --food-id "$FOOD_ID"`

**Content structure (in this order):**

1. **Title:** `# Recipe Management` (H1)

2. **Orientation paragraph:** "Load this skill when you need to create, edit, or delete recipes. This covers the full recipe lifecycle: creating, adding ingredients and steps, updating metadata, duplicating, uploading images, and deleting."

3. **Prerequisites** section (H2):
   - `RMAPI_BASE_URL` and `RMAPI_TOKEN` environment variables
   - Food and unit IDs must be resolved before adding ingredients (use `rmapi foods lookup` and `rmapi units list`)
   - `jq` recommended for extracting IDs from JSON output

4. **Full Creation Chain** section (H2) — the core ID-threading pattern:
   - Step-by-step numbered list with exact commands and jq extraction:
   ```bash
   # 1. Resolve food IDs (one HTTP call for multiple foods)
   FOODS=$(rmapi foods lookup --names "tomato,garlic,pasta")
   TOMATO_ID=$(echo "$FOODS" | jq -r '.[] | select(.name=="tomato") | .id')
   GARLIC_ID=$(echo "$FOODS" | jq -r '.[] | select(.name=="garlic") | .id')

   # 2. Get unit ID
   GRAM_ID=$(rmapi units list | jq -r '.[] | select(.abbreviation=="g") | .id')

   # 3. Create the recipe
   RECIPE_ID=$(rmapi recipes create --name "Pasta al Pomodoro" --servings-qty 4 | jq -r '.id')

   # 4. Get the auto-created default section ID
   # NOTE: A default section is auto-created on recipe creation.
   # Do NOT call sections add unless you need a second named section.
   SECTION_ID=$(rmapi recipes get "$RECIPE_ID" --fields sections | jq -r '.sections[0].id')

   # 5. Add ingredients to the existing section
   rmapi ingredients add "$RECIPE_ID" "$SECTION_ID" --food-id "$TOMATO_ID" --quantity 400 --unit-id "$GRAM_ID"
   rmapi ingredients add "$RECIPE_ID" "$SECTION_ID" --food-id "$GARLIC_ID" --quantity 3 --note "minced"

   # 6. Add instruction steps (order = insertion order)
   rmapi steps add "$RECIPE_ID" --body "Crush and saute the garlic in olive oil"
   rmapi steps add "$RECIPE_ID" --body "Add crushed tomatoes and simmer 20 minutes"
   rmapi steps add "$RECIPE_ID" --body "Cook pasta and toss with sauce"
   ```
   - After the chain, note: "Each command returns JSON with an `id` field. Thread these IDs into subsequent commands."

5. **Recipe Commands** section (H2):
   - **Create:** `rmapi recipes create --name "Name"` (required); optional flags: `--description`, `--servings-qty`, `--servings-unit`, `--prep-time`, `--cook-time`, `--total-time`, `--perform-time`, `--source-url`
   - **Update:** `rmapi recipes update <id>` with any subset of the same optional flags (only supplied fields change)
   - **Delete:** `rmapi recipes delete <id> --yes` (always include `--yes` -- agent runs in non-TTY context)
   - **Duplicate:** `rmapi recipes duplicate <id>` (creates independent copy with new id)
   - **Add Image:** `rmapi recipes add-image <id> --url "https://..."` (downloads and uploads as multipart)

6. **Section Commands** section (H2):
   - `rmapi sections add <recipe-id>` (no title = untitled) or `rmapi sections add <recipe-id> --title "Sauce"`
   - `rmapi sections update <recipe-id> <section-id> --title "New Title"`
   - `rmapi sections delete <recipe-id> <section-id> --yes`
   - `rmapi sections reorder <recipe-id> --ids "id1,id2,id3"`
   - Note: a default section is auto-created with each recipe; check existing sections before adding

7. **Ingredient Commands** section (H2):
   - Path pattern: all ingredient commands use 3-level nesting: `<recipe-id> <section-id>`
   - `rmapi ingredients add <recipe-id> <section-id> --food-id <id>` (required); optional: `--quantity 2.5 --unit-id <id> --note "chopped"`
   - `rmapi ingredients update <recipe-id> <section-id> <ingredient-id>` with optional `--food-id`, `--quantity`, `--unit-id`, `--note`
   - `rmapi ingredients delete <recipe-id> <section-id> <ingredient-id> --yes`
   - `rmapi ingredients reorder <recipe-id> <section-id> --ids "id1,id2,id3"`
   - Note: `--quantity` accepts decimals (e.g., `--quantity 0.5`)

8. **Step Commands** section (H2):
   - `rmapi steps add <recipe-id> --body "Instruction text"` (required); optional: `--title "Step Title"`
   - `rmapi steps update <recipe-id> <step-id>` with optional `--body`, `--title`
   - `rmapi steps delete <recipe-id> <step-id> --yes`
   - `rmapi steps reorder <recipe-id> --ids "id1,id2,id3"`

9. **Error Recovery** section (H2):
   - If `foods lookup` returns empty array for a name: the food does not exist; do not proceed with that ingredient
   - If `recipes create` fails with exit code 4: check `--name` is provided and not empty
   - If `ingredients add` fails with exit code 3: verify the recipe ID and section ID are valid (use `rmapi recipes get <id> --fields id,sections`)
   - If any delete command fails with exit code 4 and no `--yes`: always include `--yes` in non-TTY contexts
   - General: check exit code after each command; exit codes are 0 (success), 1 (API error), 2 (auth failed), 3 (not found), 4 (validation error)
