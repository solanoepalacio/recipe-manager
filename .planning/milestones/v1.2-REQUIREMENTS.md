## v1.1 Requirements (carried forward from prior milestone — already complete)

### Skill Bundle

- [x] **SKILL-01**: Agent can find which skill file to read for any operation (`index.md` — startup index with one-line descriptions and read guidance) — Phase 13
- [x] **SKILL-02**: Agent can authenticate and understand error codes and pagination (`shared.md` — Bearer auth, base URL, 400/401/403/404/500 meanings, pagination envelope) — Phase 13
- [x] **SKILL-03**: Agent can search and list recipes by name, food, sort, and pagination (`recipes_search.md` — GET /api/recipes with all query params, example request/response) — Phase 13
- [x] **SKILL-04**: Agent can fetch full recipe detail including sections, ingredients, steps, and images (`recipes_get.md` — GET /api/recipes/:id full response shape) — Phase 13
- [x] **SKILL-05**: Agent can create a recipe with sections, ingredients (resolved food/unit IDs), and steps (`recipes_create.md` — POST /api/recipes, GET /api/foods, GET /api/units, POST sections/ingredients/steps with recommended sequence) — Phase 14
- [x] **SKILL-06**: Agent can update or delete recipe metadata, sections, ingredients, and steps (`recipes_edit.md` — PATCH/DELETE for recipe, sections, ingredients, steps) — Phase 14
- [x] **SKILL-07**: Agent can upload and delete recipe images via multipart form (`recipes_image.md` — POST /api/recipes/:id/images multipart, DELETE image) — Phase 14
- [x] **SKILL-08**: Agent can read, create, update, and delete meal plan entries (`meal_plan.md` — GET/POST/PATCH/DELETE /api/meal-plan/entries with date range and mealType enum) — Phase 14

## v1.2 Requirements (this milestone — all complete)

### API Ergonomics

- [x] **ERGO-01**: User can filter foods by name substring (`GET /api/foods?name=<value>`) — case-insensitive; without param, full list returned unchanged — Phase 15
- [x] **ERGO-02**: User can filter units by name substring (`GET /api/units?name=<value>`) — case-insensitive; without param, full list returned unchanged — Phase 15
- [x] **ERGO-03**: User can create a recipe with inline ingredients and steps in a single request (`POST /api/recipes` with optional `ingredients[]` + `steps[]`) — all inserted atomically; existing single-field create unchanged — Phase 18
- [x] **ERGO-04**: User can look up a recipe by its slug (`GET /api/recipes/tortilla-de-patatas`) — same response shape and household scoping as UUID lookup; UUID still works unchanged — Phase 16
- [x] **ERGO-05**: User can add multiple ingredients to a section in one call (`POST /api/recipes/:id/sections/:sectionId/ingredients/batch`) — atomic insert, returns updated `SectionResponse` — Phase 17

### Skill Bundle

- [x] **SKILL-09**: Agent reading skill files can discover and use `?name=` filter on foods and units for targeted ID resolution — Phase 19
- [x] **SKILL-10**: Agent reading `recipes_create.md` can use compound create to build a full recipe in ≤3 calls (previously 11) — Phase 19
- [x] **SKILL-11**: Agent reading `recipes_get.md` (or `recipes_search.md`) can navigate directly to a recipe by slug — Phase 19
- [x] **SKILL-12**: Agent reading `recipes_edit.md` can use batch ingredient add for the edit flow — Phase 19

## Out of Scope

| Feature | Reason |
|---------|--------|

| Auth flows (login/logout) | Agent authenticates via API key Bearer token only — no session management |
| Image download/display | Skill only covers upload/delete; rendering is the consuming app's concern |
