# Fix: "Hoy" view shows hardcoded empty state instead of today's meals

## Root Cause

The "Hoy" page (`apps/web/src/app/(app)/page.tsx`) is a **static placeholder** that was never wired up to fetch data. It contains hardcoded text `"No hay recetas para hoy"` and never queries the meal plan API. The comment on line 1 says `// Hoy — populated in Phase 8 (meal planner integration)` but this was never done.

This is not a cache invalidation or timezone bug — the page simply never fetches any data.

## Relevant Files

- `apps/web/src/app/(app)/page.tsx` — **THE BUG**: static placeholder, needs rewrite
- `apps/web/src/app/(app)/planner/page.tsx` — working planner page (reference for data fetching pattern)
- `apps/web/src/lib/query-keys.ts` — query key for `mealPlan.week(from, to)`; needs a `today(date)` key
- `apps/web/src/lib/planner-dates.ts` — `localDateString()`, `MEAL_TYPE_LABELS`, `isToday()`
- `apps/web/src/lib/api-client.ts` — `api.get()` helper
- `apps/web/src/lib/auth.tsx` — `useAuth()` hook for user's name in greeting
- `packages/shared/src/api/meal-plan.ts` — `MealPlanResponse`, `MealPlanEntryResponse` types
- `apps/web/src/components/planner/MealEntryRow.tsx` — existing entry row component (can reuse or simplify)
